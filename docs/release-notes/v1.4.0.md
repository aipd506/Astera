## Before you update

* **Sessions that were running while Astera was closed end with this update.** The background Host
  now proves it is yours before Astera or `astera` talks to it, so another account on a shared
  Windows machine cannot stand in for it. That changed how the two talk, and the Host from before the
  update cannot stay. Opening Astera after the update replaces it with the new one. If you use only
  the `astera` command and do not open Astera, run `astera host start --replace` once instead.

## New features

* **The `astera` command drives Astera from any terminal.** Start and read sessions, type into them,
  plan Jobs, run them, wait for them and answer their questions, from PowerShell, cmd, a shell script,
  a CI pipeline or an agent. JSON by default, `--human` for reading, one meaning per exit code, and the
  command to run next on every error. Install it from the new **Settings → CLI** tab; on Windows it
  puts itself on your user PATH as well.
* **Your work keeps running with Astera closed.** The background Host now starts and stops workers,
  drives Jobs through their checks, reviews and repairs, and makes, merges and removes their
  worktrees, all without the app. `astera host start`, `host status` and `host stop` manage it.
* **Sessions move to another account at a usage limit even while Astera is closed.** Terminal and
  chat sessions both. When you open Astera again, it tells you in one line per session what moved,
  and Slack hears it too.
* **Chat sessions carry on without the app.** The Host takes them over when Astera quits. Each chat
  session chooses what happens to a permission question nobody is there to answer: hold it, or
  refuse after 60 seconds. `astera chats pending` and `chats answer` answer one from a terminal.
* **Slack runs in the Host**, so notices and replies keep flowing while the app is closed.
* **Jobs belong to projects, and each run of a Job is its own record.** `runs follow` prints a run's
  timeline as it happens, including what the Host did while the app was closed, `runs checks` shows
  every task's checks and verdicts, and `tasks dispatch` places one ready task by hand.
* **A command that lost its answer can be asked about, and retried safely.** Every call carries a
  request id, `requests show` says whether it arrived, and a retry with the same id is answered from
  the first attempt rather than done twice.
* **Agents can open and drive the app they are building, out of your way (experimental).** Turn on
  **Agent app workspace** in Settings → Agents. The app runs on a hidden desktop on Windows, a virtual
  display on Linux and in the background on macOS, and a purple mirror tab shows what the agent sees.
* **The file explorer handles folders of tens of thousands of files.** Only the rows on screen are
  drawn, arrow keys, Home, End and Shift+Arrow move the selection, and deleting or copying a large
  folder shows how many items are done.
* **Making a worktree shows what it is doing and can be cancelled.** It names the stage, shows the
  include copy in bytes and files, and Cancel rolls everything back.
* **The new session dialog says what it is checking.** The repository and the CLI are checked in the
  background, with a line for each, instead of the dialog freezing on a slow folder.
* **An unresponsive Host is noticed and can be replaced.** The Info tab says so and offers a button,
  and the app keeps working on its own meanwhile.
* **On Windows the Host shows up as `astera-host.exe`** in Task Manager's Details, not `node.exe`.

## Fixes

* **Astera no longer freezes on a slow network drive, a share that stopped answering or a huge
  folder.** Path checks, git calls, history reads, log and state writes and the Host's setup all
  moved off the window's thread, with a limit on how long a folder that does not answer can hold
  anything up.
* **Deleting or copying thousands of files in the explorer is fast on Windows.** A 6,000 file folder
  took about eight minutes to delete; it now takes two seconds.
* **Saving a file in the editor no longer follows a link a repository planted beside it.** It could
  overwrite a file outside the project.
* **On Windows a repository can no longer run its own `claude.cmd`, `git.cmd` or `gh.cmd`.** The CLIs
  are started from where PATH says they are, never looked up in the project folder first.
* **Another account on the same machine can no longer stand in for your Host**, on Linux (the socket
  folder) or on Windows (the pipe).
* **An agent session's `sessions send` no longer answers another terminal session's permission
  prompt.** It is refused and points to `sessions read`.
* **The start-up page and the window wear your Astera theme** instead of flashing white on a light
  mode system.
